## 📌 프로젝트 소개

사람마다 체형, 체지방률, 근육량, 생활 패턴이 서로 다르기 때문에 획일화된 운동·식단 프로그램은 효과가 떨어지거나 오히려 역효과를 낼 수 있습니다. 또한 온라인상의 운동 정보는 신뢰성이 검증되지 않은 경우가 많아, 실제 체형 개선에 성공한 검증된 사용자의 노하우를 얻기 어렵다는 문제가 있습니다.

**ComHere**는 인바디(InBody) 데이터를 블록체인에 저장해 신뢰성과 불변성을 보장하고, 사용자의 목표 체형과 유사한 성장 이력을 가진 사용자를 추천해주는 헬스 커뮤니티 서비스입니다. 사용자는 자신과 유사한 체형에서 목표 체형으로 성장한 사람을 찾아 운동법·식단 정보를 온라인상에서 안전하게 거래할 수 있습니다.

- 인바디 정보라는 민감한 개인정보를 블록체인에 기록해 위·변조를 방지
- AI가 인바디 사진을 자동으로 분석·수치화하여 수기 입력 의존도 최소화
- RAG 기반 추천 시스템으로 체형 변화 이력이 유사한 사용자를 매칭

---

## ✨ 핵심 기능

### 1. 인바디 스캔
인바디 사진을 업로드하면 Gemini API가 키, 체중, 골격근량, 체지방률, BMI 등 필요한 수치를 자동으로 추출해 JSON 형태로 반환합니다.

### 2. 체형 분류를 위한 사용자 군집화
키·몸무게·체지방량·골격근량을 기준으로 8가지 체형으로 분류하고, 스캔된 인바디가 어떤 체형에 속하는지 파인튜닝된 LLM으로 판별합니다.

### 3. 인바디 정보 등록 (블록체인)
Gemini가 인바디를 스캔함과 동시에 해당 정보를 스마트 컨트랙트를 통해 블록체인에 트랜잭션으로 기록합니다.

### 4~5. 사용자 목표치 설정 및 추천 (RAG)
사용자가 목표 체형을 설정하면 목표치를 인코딩하여 BigQuery 벡터 DB에 저장하고, 코사인 유사도 계산을 통해 목표에 부합하며 인바디 변화 추이가 유사한 사용자를 Top 3까지 추천합니다.

### 6. 블록체인 기반 사용자 간 거래
사용자 간 운동 루틴·식단 정보를 거래할 때 블록체인의 탈중앙화 특성을 활용해 중개자 없는 P2P 거래를 지원합니다.

## 🏗️ 시스템 아키텍처

```
User → Telegram → React (Frontend VM)
                     ↕
              Spring Boot (Backend VM)
              ├─ Ganache/Solidity/Remix (Block Chain Net)
              ├─ Flask (추천·시각화 서버) ↔ Google BigQuery (Vector DB) / Gemini
              ├─ MySQL (사용자·인바디·추천 데이터)
              └─ Amazon S3 (파일 스토리지)
                     ↕
                  OpenAI (체형 분류 파인튜닝 모델)
```

- **Telegram Mini App**: 별도 앱 설치 없이 Telegram 내에서 회원가입·로그인·채팅을 처리
- **Spring Boot**: 전체 서비스의 중심으로 AI 분석 서버, DB, 블록체인, 파일 스토리지 간 연동을 조율
- **Ganache / Solidity / Remix**: 인바디 데이터의 ID 및 해시값을 기록하는 스마트 컨트랙트 개발·테스트·배포
- **Flask**: 인바디 데이터를 벡터화해 BigQuery에 저장하고 코사인 유사도로 유사 사용자를 탐색
- **OpenAI / Gemini**: 인바디 이미지 OCR 및 체형 군집화 파인튜닝 모델 서빙

## 🐛 트러블 슈팅

### 1) AWS S3 Presigned URL 도입
**문제**: 인바디 결과 파일, 루틴 PDF, 게시물 이미지를 업로드할 때 서버가 파일을 직접 수신한 뒤 S3로 재전송하는 구조였습니다. 이로 인해 서버에 불필요한 트래픽·부하가 집중되었고, 클라이언트가 버킷에 접근하는 과정에서 자격 증명이 노출될 여지가 있어 보안상 취약했습니다.

**해결**: 클라이언트가 S3에 직접 업로드할 수 있도록 **Presigned URL 발급 방식**으로 전환했습니다. 백엔드는 파일 업로드 요청 시 만료 시간이 짧은 서명된 URL만 발급하고, 실제 파일 전송은 클라이언트-S3 간에 직접 이루어지도록 구조를 변경했습니다. 그 결과 서버의 파일 처리 부하가 줄었고, 자격 증명 노출 없이 제한된 시간 동안만 업로드 권한을 부여할 수 있어 보안성이 강화되었습니다.

### 2) AI 모델 파인튜닝을 통한 체형 분류 정확도 개선
**문제**: 초기에는 일반 프롬프트만으로 LLM에 인바디 수치를 전달해 8가지 체형 중 하나로 분류하도록 했으나, 체형 경계가 모호한 케이스에서 오분류가 잦아 정확도가 약 **0.72** 수준에 머물렀습니다.

**해결**: 수천 건의 인바디 데이터(키·체중·체지방률·골격근량 등)를 라벨링한 학습 데이터셋을 구축하고, **OpenAI GPT-4.1 mini 모델을 파인튜닝**했습니다. 그 결과 loss는 0.7 → 0.007로 감소했고, 분류 정확도는 **0.72 → 0.97**로 크게 향상되어 실제 서비스에 적용 가능한 수준의 신뢰도를 확보했습니다.

### 3) 블록체인-DB 간 데이터 일관성 문제
**문제**: 인바디 정보를 블록체인과 BigQuery(벡터 DB)에 각각 저장하는 이중 저장 구조에서, 두 저장소 간 데이터 값이 불일치할 가능성이 있었습니다.

**해결**: 인바디 데이터를 저장할 때마다 **해시값을 생성해 비교하는 알고리즘**을 도입했습니다. 블록체인에 기록된 해시값과 DB에 저장된 데이터로부터 재계산한 해시값을 비교함으로써 위·변조 여부와 데이터 일관성을 함께 검증할 수 있도록 했습니다.
